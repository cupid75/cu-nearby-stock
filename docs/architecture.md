# 설계 이유와 데이터 처리

## 서버 하나에서 화면과 API 제공

FastAPI가 `static/`의 화면과 상품·재고 API를 함께 제공합니다. 화면 서버를 따로 운영하지 않아 배포 구성을 단순하게 유지했습니다. CU 요청 함수는 `cu_stock_check.py`에서 재사용합니다. 데이터베이스와 회원가입은 현재 범위에 포함하지 않았습니다.

```text
브라우저 ── 상품 검색·재고 요청 ──> FastAPI ──> CU 조회
         <── 필요한 필드와 상태 ──       <── 원본 응답
브라우저 ── 지도·장소 검색 ──────> Kakao Maps SDK
```

## 화면과 검색 흐름

메인 화면은 상품 검색, 결과 화면은 위치·지도·매장 목록에 집중합니다. 일반 검색은 사용자가 정확한 상품을 선택합니다. 빠른검색은 공백을 제거한 상품명 끝부분이 버튼의 상품명과 일치하는 후보가 하나일 때만 바로 선택합니다. 후보가 없거나 여러 개면 선택 목록을 보여줍니다.

위치가 이미 있으면 상품 선택 후 재고를 한 번 조회합니다. 위치가 없으면 위치 선택을 안내하고 GPS를 자동 요청하지 않습니다. 메인과 결과 사이에서는 화면 메모리의 선택을 유지하고 새로고침하면 초기화합니다.

## 재고 상태와 거리

수량이 양수면 재고 있음, 0이면 품절, 수량을 해석할 수 없으면 미확인으로 구분합니다. 연결 실패나 접근 거절은 오류 안내로 처리하며 품절로 바꾸지 않습니다. 좌표가 없는 매장은 지도에서 제외하고 개수를 별도로 안내합니다.

기본 목록과 지도는 재고가 있는 매장을 보여줍니다. 품절·미확인은 목록 옵션으로 확인합니다. 선택한 위치와 매장의 직선거리로 반경 1·2·5km를 적용하고 가까운 순으로 정렬합니다. 도보·차량 이동거리가 아니며 CU가 반환하지 않은 주변 매장까지 찾는 기능은 없습니다.

## 캐시와 요청 제한

캐시는 같은 결과를 잠시 보관해 외부 요청을 줄이는 장치입니다. 상품 검색은 10분, 동일 상품·좌표의 재고는 30초 동안 보관합니다. 반경만 바꾸면 같은 응답에서 다시 필터링하고 원래 조회 시각을 유지합니다.

익명 브라우저 쿠키 기준 분당 10회, 연결 IP 기준 분당 60회 제한을 둡니다. 쿠키는 로그인 계정이 아니므로 동일인을 완전히 식별하지 못하며 공용 네트워크는 IP 제한을 공유할 수 있습니다. 캐시·제한은 한 프로세스의 메모리에 있어 서버 재시작 시 초기화됩니다. 이 때문에 운영 명령은 `--workers 1`을 사용합니다.

## 위치와 키 관리

GPS는 버튼을 누를 때 `getCurrentPosition`을 한 번 호출합니다. 위치를 지속 추적하지 않습니다. 실패하면 동네·역 이름 검색으로 대체할 수 있습니다.

좌표는 재고 조회 본문으로 서버와 CU에 전달하고 서버 캐시 키로 30초간 일시 사용합니다. 만료 항목은 1초 주기 정리 작업과 캐시 접근 시 정리합니다. 정상 실행 시 약 31초 이내 제거되며 화면 메모리는 새로고침 전까지 유지됩니다. 위치를 파일·DB·URL·브라우저 저장소에 저장하지 않으며 운영 명령에서 접근 로그를 끕니다.

키는 환경 변수로 설정하고 저장소에 넣지 않습니다. 카카오 JavaScript 키는 지도 SDK 특성상 브라우저에 전달되므로 허용 도메인으로 사용 범위를 제한합니다. 세션 서명용 `SESSION_SECRET`은 서버에서만 사용합니다.

## API 구성과 한계

| 경로 | 역할 |
|---|---|
| `GET /health` | 서버 실행 상태. CU 연결 성공을 보장하지 않음 |
| `GET /api/config` | 지도용 JavaScript 키 설정 제공 |
| `POST /api/products` | 상품 검색 |
| `POST /api/stock` | 상품과 좌표로 주변 재고 조회 |

CU 공식 공개 API로 제공·지원되는 연동이 아닙니다. 접근 정책과 응답 형식이 바뀌면 작동하지 않을 수 있습니다. 401·403·429와 연결 오류는 자동 재시도하지 않습니다. 로그인·알림·즐겨찾기·여러 서버 간 공유 캐시는 구현 범위에서 제외했습니다.
